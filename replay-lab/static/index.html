HOW THIS ENVIRONMENT WORKS

How replay works

Preparation reads the selected Wazuh, AMiner, and optional native telemetry files, extracts structural fields, and sorts records by their actual timestamps. It does not classify them. Ingestion IDs and sensor IPs are never substituted for event timestamps or actor identities.

  1. Replay. Event-paced mode spreads the ordered records across the selected duration, compressing quiet gaps. Time-scaled mode advances the original clock evenly. Pause freezes ingestion; Step advances one record.
  2. Classify. Versioned rules inspect the current record and bounded windows of earlier observations. Distinct flow fan-out, authentication failures, and DNS sequences can supply a signal. Encoded command parameters are decoded as data and never executed. A request is not proof of execution.
  3. Group. Records with the same rule family, observed source, and host form an episode. Thirty minutes of inactivity starts a new episode. Detector repeats remain counted, with distinct evidence counted separately.
  4. Connect. Signals connect within 15 minutes on the same observed source and host. Privilege or service records can connect by host and time alone; those weaker edges remain dashed. Shared source/destination IP or same-host account fields can also connect episodes. All relationships are inferred; matching fields are confirmed evidence only when supported by the cited alert IDs. No attack success is assumed.
  5. Investigate. Review a group with up to three host-and-time queries. Each query records evidence, an empty result, or a failure, followed by a thesis, benign challenge, and qualified verdict. Queries can retrieve only records already received in the selected dataset.
  6. Verify. The inference pipeline never opens labels.csv. A separate endpoint can read it only after completion, to compare frozen results with temporal attack windows.

The original alerts and selected native logs have uneven visibility. A quiet window does not mean a safe system. Training-mode anomalies stay marked, and labels cannot establish record-level precision or recall.

Research direction: bounded evidence, inspectable grouping, and uncertainty-aware incident review. Classification uses transparent rules. Optional AI node analysis explains the selected evidence and suggests next steps; configure OPENAI_API_KEY on the server to enable it.
